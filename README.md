# AI Action Plan RFI — a discourse corpus

What did organizations ask for, and what made it into federal policy?

The Federal Register notice [90 FR 9088](https://www.federalregister.gov/documents/2025/02/06/2025-02305/request-for-information-on-the-development-of-an-artificial-intelligence-ai-action-plan)
states that its purpose was to inform an AI Action Plan. That plan was published in
July 2025, which makes the pairing an administrative record rather than an inference:
the submissions are the input and the plan is the output.

This repository holds those submissions in a documented schema, and a
browser-based viewer for reading and annotating them.
`America's AI Action Plan` is the anchor the corpus is read against.

**Status:** work in progress (DS 7400, Fall 2026).

## Contents

| Path | What it is |
|---|---|
| `pipeline/` | Adapters and scripts that build the corpus from source documents |

| `backend/` | FastAPI + SQLite store for the annotations |

### On the DOL AI Literacy Framework

An earlier version of this project treated the framework as an outcome of the RFI.
That was wrong. [TEN 07-25](https://www.dol.gov/agencies/eta/advisories/ten-07-25)
states its own basis as Executive Order 14277 on AI education for American youth, and
cites neither the RFI nor the OSTP process. The framework is kept here as context for
interpretation; it is not the document the submissions are measured against.

### Provenance of derived fields

The [IFP AI Action Plan Database](https://www.aiactionplan.org) supplies the index:
which submissions contain recommendations, and roughly where each one sits. Its
derived fields are generated by `claude-3-7-sonnet-latest` and published without
validation figures, so this repository checks them rather than trusting them.

**`Full text` is not consistently a quotation.** Every segment is matched against the
submission it claims to come from, ignoring case, whitespace and punctuation
(`scripts/05_match_fulltext.py`), and the verdict is stored on the segment:

| `source_match` | Segments | Meaning |
|---|---|---|
| `exact` | 3,232 (63%) | Found in the submission. `char_offset_in_doc` is filled |
| `partial` | 391 (8%) | Some lines found, some not |
| `none` | 1,513 (29%) | Not found |
| `unavailable` | 30 (1%) | The submission text could not be extracted, so no check was possible |

`none` means **not found**, not **invented**: a real quotation goes undetected when a
PDF extracts badly, and inspection shows both causes present. Treat those segments as
unverified. The viewer hides them by default and offers a toggle.

Where excerpts could be located, they cover a median 20% of the submission and 90%
of them begin at a line or bullet, so the unit IFP extracted is a structural one —
a bullet, or a heading with the paragraph under it — not an arbitrary span.

On the other derived fields:

- `org_type_ifp` is retained but **is not used as an analysis variable**; `org_type_official` is reserved for the NITRD-declared respondent type.
- Segment text originates from the IFP `Full text` extraction and is marked with `layer`, so full-text paragraphs can later coexist under the same documents.

Raw source archives (`pipeline/data/raw/`, 603 MB) are not committed. Download them
from [NITRD](https://www.nitrd.gov/coordination-areas/ai/90-fr-9088-responses/).

## Running the viewer

Requires Node.js 20 or later.

```bash
cd viewer
npm install
npm run dev
```

Then open the URL printed in the terminal (usually http://localhost:5173).
